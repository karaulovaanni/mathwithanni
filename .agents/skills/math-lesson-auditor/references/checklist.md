# Чек-лист качества урока

Используй как банк проверок — выбери пункты, уместные для темы. Не ставь галочку без фактического подтверждения.

## 1. Математика

- [ ] Определения и термины без искажений и круговых объяснений.
- [ ] Во всех типовых задачах и примерах самостоятельно вычислен правильный ответ.
- [ ] Ограничения на знаменатель, подкоренное выражение, отрезки, меры углов отражены в заданиях.
- [ ] Нет лишних/недостающих решений после преобразований.
- [ ] Чертёж математически соответствует данным, отметки сторон/углов не добавляют несуществующие условия.
- [ ] Обозначения и соответствие вершин единообразны.
- [ ] Дроби изображаются равными частями; точки на числовой прямой стоят в вычисленных координатах.
- [ ] Проценты согласованы с базой 100%; не путаются часть, целое и процент.
- [ ] Генератор не создаёт некорректных, двусмысленных задач или повторов, если повторы запрещены.

## 2. Методика

- [ ] Урок начинает с ясной цели и доступной опоры на знакомое.
- [ ] Новая идея объясняется через рисунок/эксперимент/пример и затем формализуется.
- [ ] Есть разобранный пример и самопроверка после самостоятельной попытки, если тип урока этого требует.
- [ ] Достаточно практики разных форматов без искусственного усложнения.
- [ ] Отработка целевого навыка отделена от проверок случайных несвязанных навыков.
- [ ] Неверный ответ приводит к полезной обратной связи, а не только красному цвету.
- [ ] Подсказка помогает рассуждать, не раскрывая весь ответ сразу.
- [ ] Нет ложной геометрической интуиции «так выглядит, значит равно».

## 3. Ученик

- [ ] За 10–20 секунд понятно, что делать в этом разделе.
- [ ] Никаких нерасшифрованных обозначений на рисунках.
- [ ] Неизвестные слова объяснены; фразы короткие, но математически точные.
- [ ] Можно исправить ответ и повторить попытку без запутывания.
- [ ] Понятно, чем закончился номер/блок и как перейти дальше.
- [ ] Нет «пустых» кнопок и элементов, выглядящих интерактивно, но не работающих.

## 4. UX/доступность

- [ ] 360/768/1366 px (если доступно реальное воспроизведение).
- [ ] Шрифт и формулы читаемы, рисунки не обрезаны, прокрутка ожидаема.
- [ ] Кнопки и ссылки имеют заметные состояния focus/hover/disabled.
- [ ] Клавиатурные действия не перехватываются внутри поля ввода ошибочно.
- [ ] При переходе в раздел начало раздела видно.
- [ ] Нет дублирующихся блоков и неоправданных ступеней сложности.
- [ ] Цвет не является единственным источником информации о правильности.
- [ ] Значимые рисунки имеют доступное объяснение или альтернативу, если нужно.

## 5. Техника/регрессия

- [ ] Нет ошибок консоли при открытии и прохождении, если доступен браузер.
- [ ] Все ссылки, CSS, JS, изображения подгружаются по допустимым адресам.
- [ ] Не появилось дублированных HTML `id` и конфликтующих обработчиков.
- [ ] Ввод пустого/невалидного значения обрабатывается.
- [ ] После смены задания не остаются чужие подсказки, ответы и цвета.
- [ ] После обновления страницы состояние соответствует согласованной логике.
- [ ] Случайная генерация проверена сериями (минимум 50 вариантов, когда возможно; критичные крайние случаи отдельно).
- [ ] Перенос по стрелкам соответствует ТЗ и не ломает ввод.
- [ ] Каталог, старые редиректы, query/hash и возврат продолжают работать.
- [ ] Для изменённых экранов выполнены приёмочные сценарии, а соседние разделы не регрессировали.

## Как отмечать проверку

Используй `PASS`, `FAIL`, `NOT TESTED`, `NOT APPLICABLE`. В отчёте рядом с `FAIL` — воспроизведение; рядом с `NOT TESTED` — чего не хватило (доступ/браузер/файл).
