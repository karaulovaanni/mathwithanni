# Контекст проекта и предпочтения

## Факты из README репозитория (прочитано 22 ноября 2026)

- `karaulovaanni/mathwithanni` — статический сайт «Матемастерская» на GitHub Pages.
- Главная страница — `index.html`, каталог по классам.
- Уроки в отдельных папках с собственным `index.html`; специальные JS-файлы уроков располагаются рядом.
- `3-klass/matematika/`: 3 класс; `5-klass/matematika/`: в том числе `drobi-master` как единственный канонический урок дробей; `5-klass/geometriya/`; `6-klass/matematika/`; `8-klass/algebra/`; `trenazhery/`; `assets/`.
- Корневые HTML (кроме главного) — короткие перенаправления, сохраняя query и hash.
- `assets/catalog.js`: сохраняет открытые классы и прокрутку для возврата из урока в этой вкладке. Обновление главной сбрасывает открытые классы.
- PDF размещены в Google Drive; в репозитории только WebP-превью и ссылки в каталоге.
- Список и структура могут измениться: всегда сверяй актуальный README и файлы репозитория.

## Установленные образовательные ориентиры пользователя

- Аудитория: 3–8 классы, в том числе углублённые программы. Приоритет не «больше весёлых кнопок», а **математическое понимание**.
- Интерактивы должны объяснять действие/понятие, а не только давать выбрать ответ.
- Для 5 класса дроби: доля и дробь; равное деление; числовая прямая с правильными засечками и подписями; сравнение; равные дроби; правильные/неправильные; визуальные пицца/торт/ленты и задания по рисункам.
- Для 6 класса проценты: модель батареи, стакана, интерактивная таблица 100%–1%–x%; разные типы задач; пошаговая логика; перевод дробей и процентов. Отображение ответа и стирание полей должно соответствовать ТЗ конкретного урока.
- Для 7 класса отношения и пропорции: недостаточно одной теории и нескольких кнопок; нужны модели, понятные соотношения и визуальные примеры.
- Для геометрии 7–8: точные чертежи, признаки равенства/подобия, модели с изменением формы и размеров; внимание к соответствию вершин, сторонам и углам.
- Для 8 класса корни: уметь объяснить, когда появляется модуль и почему; проверять записи преобразований.
- Читаемое оформление: умеренный цвет, без лишней декоративности, без дублирующихся тренажёров и необоснованного множества уровней; текст и формулы крупные и ясные.
- При переходе между частями урока пользователь ожидает попадать к началу выбранного раздела.
- В отдельных тренажёрах согласован переход по номерам стрелками влево/вправо; не делай это универсальным требованием для всех экранов.
- Отвечать на запрос пользователя по существу: если требуется ТЗ — сделать ТЗ, если изменение — изменение, если аудит — аудит.

## Принцип применимости

Эти пункты — **ориентиры**, а не свидетельство реализации. В любом аудите отделяй уже внедрённое от предлагаемого и следуй актуальному заданию пользователя. Не объявляй отсутствие какой-либо модели ошибкой, если она не нужна для проверяемой темы.
